# README visual assets

These assets are original, editable SVGs for the repository landing page. They reuse the existing TTT mark geometry from `public/brand/ttt-primary.svg`, with a graphite, white and red presentation palette. They do not change the application's branding or theme.

- `hero.svg` and `hero-static.svg`: self-contained title and decorative comparison trace. CSS draws the line and reveals the title once, then stops. `prefers-reduced-motion: reduce` removes both animations. The README also selects the dedicated static variant with a reduced-motion `<picture>` source; the static default contains the complete trace and readable text.
- `comparison.svg`, `track.svg`, `analysis.svg`, `video.svg`: abstract feature illustrations, not measured data or simulated screenshots.
- `architecture.svg`: the implemented local telemetry path; platform video frameworks are identified separately.
- `platforms.svg`, `download.svg`: static availability/navigation badges. Release version and CI status use live release/workflow badges in the README. There are no download-count claims or scheduled README-writing workflows.

All SVGs use explicit dark surfaces and high-contrast text, so the same artwork works on GitHub's light and dark pages. They use system fonts, fluid view boxes, accessible titles/descriptions, no scripts, no external resources, no raster embeds and no filters. GitHub Markdown controls page layout; CSS is contained inside SVG images only.

The large application screenshot is reused from `website/assets/telemetry.webp` (1440 × 900). The optional Advanced preview uses `website/assets/advanced.webp`. Both are authentic captures of the shared application interface running with **synthetic browser-demo data**, generated by `scripts/capture-website-previews.mjs`; neither is a fabricated UI or a claim of real driving results. See `website/README.md` for capture provenance. Do not refresh these assets from private recordings for a public README.

The stable installer links are intentionally pinned to the verified v0.1.3 assets. When a new release ships, update the platform/download table and availability text after inspecting that release. The separate latest-stable and all-releases links remain current automatically. AI coaching is labeled in development because it is absent from the published v0.1.3 installers.

Documentation validation uses GitHub's GFM rendering API, XML parsing, local browser inspection at desktop/mobile sizes in both themes, reduced-motion checks and link checks. No application build or native test suite is needed for these presentation assets.
